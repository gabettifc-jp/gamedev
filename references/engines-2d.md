# 2Dの絵を出す道具（Canvas 2D とゲームエンジン）

- **調べた日：2026-08-22**
- **調べた理由：**がべ ──「**全体的に安っぽいな。これ以上はゲームエンジンとか使わないと無理か。**」
- **軸：**速さの比べ合いではなく、**「平たい・輪郭が太い・色数が少ない見下ろし」の画風に限って、何が変わるか。**

---

## 1. エンジン（WebGL）でしかできないこと

出どころ：https://www.tutorialpedia.org/blog/is-there-any-reason-for-using-webgl-instead-of-2d-canvas-for-2d-games-apps/

| できること | Canvas 2D では |
|---|---|
| **シェーダ（GLSL）を書いて、画素と頂点を GPU で直接いじる** | **できない。**決まった描画命令しか無い |
| **フレームバッファに描いて、GPU の上で後処理する** | `OffscreenCanvas` は在るが、**GPU 上に留めておけない** |
| **合成の式を自分で決める**（加算・減算など） | **決められた合成しか無い** |
| **16/32ビット浮動小数の色**（HDR） | **8ビット（0〜255）に固定** |
| **同じ絵を一回の命令で大量に描く**（インスタンシング） | **一個ずつ描くしかない** |
| **拡大の補間を選ぶ／ミップマップ** | **常に線形補間。**ドット絵を拡大するとぼける |

> 原文（拡大の件）：Canvas 2D "uses linear filtering globally, making pixel art appear blurry when scaled"

## 2. 数字

### 物量

出どころ：https://www.pkgpulse.com/guides/fabricjs-vs-konva-vs-pixijs-canvas-2d-graphics-2026

> **Canvas は 50個くらいまでの簡単な動きなら問題ない。PixiJS は 1000個以上を 60fps で動かすところで効いてくる。**

### 積み荷の重さ

| 道具 | 記事の言い値 | **実際に入れて測った値（2026-08-23）** |
|---|---|---|
| **PixiJS** | 約 200 KB | **`pixi.min.mjs` 800 KB**（＋`pixi-filters` 212 KB） |
| **Phaser** | 約 500 KB | **`phaser.min.js` 1.4 MB**（4.2.1） |
| **Godot（web 書き出し）** | 9 MB から（圧縮前） | 未測定 |

> **【訂正】記事の数字は古い。**
> 「PixiJS 200KB／Phaser 500KB」は **Phaser 3 の頃の値**である。
> **実際に npm から入れて測ると、PixiJS 8.20.0 が 800KB、Phaser 4.2.1 が 1.4MB。**
> 桁は変わらないが、**倍以上ちがう。**

出どころ：https://generalistprogrammer.com/comparisons/phaser-vs-pixijs ／
https://best-games.io/blog/godot-web-export-optimization-guide

> **Godot 4.0 beta4 の時点で、「空の2Dノード一つ」の HTML5 書き出しが 40MB を超えたという報告がある**
> （https://github.com/godotengine/godot/issues/68647）。**いまの版では改善しているが、桁は変わっていない。**
> web では **50MB は「巨大」**とされ、まず初期の積み荷を減らせと言われている。

## 3. Godot 4 の 2D が標準で持っているもの

出どころ：https://github.com/godotengine/godot-docs/blob/master/tutorials/2d/2d_lights_and_shadows.rst ／
https://www.gdquest.com/tutorial/godot/2d/lighting-with-normal-maps/ ／
https://wolfinabowl.itch.io/godot-luma-mapping-shader

- **2Dの光源と影**が最初から在る
- **法線マップ**を絵に添えると、**画素ごとに光の当たり方が変わる**（平たさが消える）
- **CanvasTexture** が「色・法線・つや」の三枚を一組で持てる
- **ルママッピング**で、入ってくる光を段に丸めて**トゥーン調にできる**

## 4. **この画風に限って、何が変わるか**（ここが本題）

### 変わるもの

| 何が | どう変わるか |
|---|---|
| **物量** | 50個 → 1000個以上。**船・鳥・波・粒・数字が大量に飛ぶ画面**が作れる |
| **画面全体の後処理** | 光のにじみ、色調、画面の端の暗さ。**いまは一切できない** |
| **輪郭** | いま**同じ形を8回ずらして描いて**輪郭にしている。シェーダなら一回で、しかも太さが均一になる |
| **絵を貼る道具立て** | 描いた絵を並べる・切り替える・アニメさせる仕組みが最初から在る |

### **変わらないもの**

**一枚の絵の密度。**

**これは描いた量で決まる。**エンジンを替えても、木が生えるわけでも、波が立つわけでもない。
`references/art-stylized.md` §8 の一行がそのまま当たる ──

> **安っぽさの原因はポリゴン数ではなく、面の上に何も乗っていないこと**

### そして、**この画風は WebGL の主戦力を使わない**

Supercell は「**PBRを多くの点で壊す**」「**現実より粗い素材にする**」と言っている（`art-stylized.md` §1）。
**平たい・輪郭が太い・色数が少ない**画風は、
**シェーダも法線も光源も HDR も、ほとんど出番が無い。**

**つまりエンジンの効き目が、いちばん薄い画風である。**

## 5. 結論（**こちらの見立て。承認は要らないが、鵜呑みにもしないでほしい**）

**いまの安っぽさは、道具では説明できない。**

- 見本21（260体が群れる）と見本23（がべが「かなり好き」と言った地図）は、**同じ Canvas 2D で出ている**
- いま足りていないのは、**木・波の泡・深浅の帯・都市の描き込み・影・UIの板・全体のゆっくりした動き**
- **どれも Canvas 2D で描ける。**描いていないだけ

**エンジンに移す値打ちが出るのは、次のどれかが要るとき。**

1. **画面に数百〜数千の物が同時に居る**（いまの spice-lanes は都市が十数個）
2. **画面全体にかかる後処理**（光のにじみ、色調）が絵の柱になる
3. **絵を大量に描いて貼る**作りに変える（＝描く量が本体になる）

**3 が本命だと思う。**ただしそれは**エンジンの話ではなく、絵を何枚描くかの話**である。

## 5-b. 実際に入れて動かした（2026-08-23）

**三つとも、この環境で動いた。**見本24（PixiJS）と見本25（Phaser）が `spice-lanes/builds/` に在る。

### PixiJS 8.20.0（＋ pixi-filters 6.1.5）

**入れたもの：**画面全体の色調（`ColorMatrixFilter`）／航路の光のにじみ（`GlowFilter`）／
海の揺らぎ／**粒 1200個**。

**分かったこと。**
- **効いたのは、航路の光のにじみだけ。**線が生きて見える
- **粒 1200個は、雪か砂嵐に見えた。**数を出せることと、絵が良くなることは別
- 色調は少し鮮やかになるだけ

### Phaser 4.2.1

**入れたもの：**カメラの寄り引き（`zoomTo`／`pan`）と画面の揺れ（`shake`）／
トゥイーン（都市が跳ねて出る・数字が 0 から 3,919 へ伸びる）／粒の噴き出し口。

**分かったこと。**
- **これは「絵の道具」ではなく「作りを速くする道具」である。**
  カメラ・トゥイーン・入力・場面の切り替え・絵の読み込みが最初から在る。
  **こちらは spice-lanes でこれを全部手で書いていた**（camX/camY、bob、ボタンの当たり判定）
- **描く力そのものは PixiJS と同じ WebGL。**見た目は良くならない
- **Graphics に曲線の道が無い**（`quadraticCurveTo` に当たるものが無く、`Phaser.Curves` を別に使う）。
  **見本25の海岸線が角ばっているのはそのため。**いまの Canvas 2D のほうが曲線は素直に引ける

### 三つを並べた結論

| | 絵が良くなるか | 何が良くなるか |
|---|---|---|
| **Canva** | **なる可能性がある** | **描く量を外から持ってこられる**唯一の道 |
| **PixiJS** | **ほとんどならない** | 物量・光のにじみ・色調 |
| **Phaser** | **ならない** | **作るのが速くなる**（カメラ・トゥイーン・入力・場面） |
