# 触ってもらうときの相場

**生の記録は `references/playtest.md`（39件）。ここはそこから落とした相場の表である。**

`templates/mihon.md`（手触りの見本の作り方）と対になる。あちらは**作り方**、ここは**触らせ方**。

## 枠について（先に断る）

**下の切り方は、こちらが置いたものである。**
調べる前に渡した七つの枠（規模と時機／何を測るか／何を聞くか／見ているあいだ／
声の扱い／機械にやらせる／間違えた話）は、**調べた側から五つの文句が返ってきた。**

- 「何を測るか」と「機械にやらせる」が同じもの（指標の設計）を別角度から見ていた
- 「何を聞くか」と「見ているあいだ」は実務上ひとつ（黙るのと聞き返すのは同じ規則の表と裏）
- 「規模と時機」は二つの問い（何人か・いつか）が混ざっていた
- 「間違えた話」は分野ではなく**視点**だった（中身は他の分野に分解できる）
- **実務者の書いたものは分野を跨ぐのが普通**で、渡した枠は研究論文寄りの切り方だった

**渡した枠に入らなかったものも五つ返ってきた**（調達／頼まれた側の心理／複数人の場の司会／
測ったあとの政治／公開後に消えない評価）。**下はそれを入れて切り直したものである。**

## 1. 誰に頼むか

| 相場 | 出どころ | 外すと何が起きるか |

| **人数は目的で決まる。**問題探しなら **6人**（no-show を見込んで5人+1）、人を理解するなら **12人**、量を測るなら **100人** | 〔Bromley〕 | 目的に足りない人数で測って、出た数字を信じる |
| **「面白いか」を測るには 25〜35人要る。**6〜12人では読めない。**ユーザビリティと面白さは別物** | 〔Player Research〕〔PlaytestCloud〕 | 少人数の「面白かった」を面白さの証拠として使う |

## 6. 機械にやらせる

**この節がいちばん厚い。**研究の一次資料が5本ある。

| 相場 | 出どころ | 外すと何が起きるか |
|---|---|---|
| **★エージェントの数値は、絶対値としては使えない。差分としては使える。**「絶対値ではエージェントは人間の水準に届かないが、**レベル間の挙動の差は人間の挙動の差と強く相関する**。したがって、劣った性能でありながら、エージェントの性能を使ってプレイヤーの指標を推定することは可能である」 | 〔Kristensen ほか〕約900,000人と比較 | **絶対値として読むと、そこで全部が狂う** |
| **エージェントの数値は人間の数値に線形に対応しない。**理由が5つ挙がっている（**エージェントは人間よりずっとランダムでない**／深い戦略を要する場面で人間のほうが成功率が高い／平均の限界／難度上昇への感度が違う、ほか）。**人間データから写像を当てはめないと絶対値は出ない** | 〔King / Candy Crush〕 | エージェントの成功率をそのまま難度として読む |
| **LLM でも同じ構図。**「LLM は平均的な人間ほど上手くないが、**統計的に有意で強い相関**を示す」 | 〔Xiao & Yang〕Wordle で r=0.624 | |
| **★指標ごとに「平均を使うか、上位だけ使うか」が違う。**AI の pass rate は**全走行の平均**が最良、moves left は**上位15%**、cleared goals は**上位5%**が最良 | 〔Rovio〕95,266人の実データ | **全部を平均で読むと、指標によっては相関を落とす** |
| **上位だけを使う理由。**エージェントの手数は**長い裾を引く分布**になる（手数に上限が無く、環境が確率的なため）。**良い走行だけを使うと分布が締まり、人間の正解に近づく** | 〔Rovio〕 | |
| **機械と人間は、得意な仕事が逆。**人間はタスクを**100%**こなすが仕込んだバグは**18%**しか見つけない。LLM エージェントはタスク**95%**・バグ**82%** | 〔TITAN〕 | どちらかで置き換えようとする |
| **AI は「六分間 混乱していた」を教えてくれない。**「オンボーディングを技術的に完了したことは言えるが、**実際のプレイヤーが六分間 混乱していたことは言えない**」 | 〔VGM〕**業界ブログ。測定に基づく主張ではない** | 完了ログを体験の証拠にする |
| **合成ユーザー（AIに人間役をさせる）は別の罠。**迎合する／**何にでも関心があるように見えて優先順位が付かない**／**行動データが出ない**。「実ユーザー調査の置き換えに使うな。出たものは**検証すべき仮説**として扱え」 | 〔Nielsen Norman Group〕 | **合成ユーザーは「言ったこと」を捏造し、エージェントは「したこと」しか出さない。****どちらも「言ったことと したことの差」を再現しない** |
| **クライアントを通すと、ゲームではなくクライアントを測る。**EA は実物のクライアントを使わず、**仕組みだけを別システムに作り直した** | 〔EA / The Sims Mobile〕**理由の記述は要旨に無く、本文未取得** | |
| **現場は懐疑的である。**「ゲーム開発者は、テストに自動エージェントを使うことに**懐疑的である**」。研究側が向かうべきは **testing oracle（何をもって正解とするか）** | 〔Politowski ほか〕 | 研究の熱をそのまま現場の相場だと思う |
| **速さは桁で変わる。**新レベルの難度推定が**7日 → 1分未満** | 〔King〕 | |
| 〔相場が取れなかった〕 **AIの通し時間と人間の通し時間の対応表** | どの論文も「難度」「pass rate」「手数」は人間と突き合わせているが、**時間を突き合わせた例が一件も無い** | |

## 当たり前になっているが、理由が書かれていないもの

**全員がやっているのに、なぜかを数値で示した資料が一件も無いもの。**
**やるなとは言わないが、「相場だから」以上の根拠は無いと知っておく。**

- **「助けない」** ── 三つの資料が言うが、**助けたときと助けなかったときで結果がどう違うかを測った例がゼロ**
- **think aloud を使うこと** ── **しゃべらせることでプレイが変わる可能性**に触れた資料が一つも無い
- **「作者はテストに参加しない」** ── 理由を書いたのは一件（採点が甘くなる）だけ、他は前提にしている
- **セッションが90分／2時間であること** ── **なぜその長さかは、どちらも書いていない**
- **エージェントを1レベルあたり100回／1000回走らせること** ── **回数の決め方の根拠が無い**

## 出どころが一件しかないもの

**引くときは「一件しか無い」と添える。**

- 「面白いか」を測るには最低25〜35人〔Player Research〕
- **上位5%／15%の走行だけを使うと相関が上がる** ── 元の仮説は〔Kristensen〕一件（〔Rovio〕はその追試）
- **"happy face syndrome"** という名前〔Zimmerman〕
- 一回2時間・200セッション・**うち約半分がリピーター**・1セッション約100 action items〔Valve 1999〕
- いらだちの5指標と、**22人中6人が一致**〔Drachen ほか〕
- Battlefield V は601機能・0.5M時間・**約300人年**〔EA SEED〕
- GEQ の7因子構造が **N=633 で再現しなかった**〔Law ほか〕**しかも二次**
- **「テストプレイは最低100回」**〔米光一成〕**本人が「各自調整してください」と付けている**

## 昔と今で変わったもの

**「テストプレイ」の意味が、部屋に人を呼ぶこと → ログを取ること → 人を呼ばないこと へ動いている。**

| いつ | 何をしていたか |
|---|---|
| 1999〔Valve〕 | **観察とメモだけ。**「遅い」という問題意識が無い（2年かけている） |
| 2013〔Square Enix / IO Interactive〕 | **1秒間隔のテレメトリ＋地図解析** |
| 2018〔King〕 | 人間のログから学習したエージェント。「遅い」が明示的な問題になる（**7日 → 1分未満**） |
| 2021〔Rovio〕 | **人間を呼ばずに、95,266人分の実データにエージェントを当てる** |
| 2025-26〔TITAN／スクウェア・エニックス〕 | **画面を見て UI を操作する。**仕込みが要らない代わりに、**描画とアニメーションの待ち時間がそのまま計測に乗る**はずだが、**どちらの資料もそのことに触れていない** |

**人間のテスターの弱点についての認識も変わった。**
「テストプレイヤーの技量分布は一般プレイヤーの分布と違うので、結論が一般化しない」〔King 2018〕は、
1999年の資料には出てこない論点である。

## 外していたもの（直す）

### 1. Claudeに「面白いか」を聞いてはいけない

**合成ユーザーの三つの限界〔Nielsen Norman Group〕がそのまま当たる。**
迎合する／何にでも関心があるように見えて優先順位が付かない／**行動データが出ない。**

> **合成ユーザーは「言ったこと」を捏造し、エージェントは「したこと」しか出さない。**
> **どちらも、人間の「言ったことと したことの差」を再現しない。**

- Claudeが出した「こうすると良さそう」は、**検証すべき仮説として扱う**（相場の言い方どおり）

### 2. 指標ごとに「平均か上位か」を選ぶ

〔Rovio〕が95,266人の実データで測っている ──
**pass rate は全走行の平均、moves left は上位15%、cleared goals は上位5%が最良。**

**こちらの測定器は、全部を平均で読んでいる。**
理由は「エージェントの手数が長い裾を引くから」で、**同じことが起きているなら同じ手が要る。**

### 3. 「作者はテストに参加しない」を、構造上守れない

〔WAZA games〕「作り手側がプレイヤーになったが最後、**採点が甘くなりがち**」。
**この手順は、設計者が自分で触ることを段階8に置いている。**守れない。

**守れないと認めたうえで、効く対策だけ採る。**

- **触る前に、Claudeが「ここはこう押してください」と説明しない**（相場3「説明しない」）
- **触ったあとの生ログを、その場で書く**（`friction.md`）。あとで思い出すと、都合よく塗られる

### 4. 初見が一度しか取れない問題を、抱えている

〔wayline〕「知り合いを使い切ると、新しい初見が手に入らなくなる」。
**設計者は毎回遊び込んでいるので、二回目以降の初見が原理的に取れない。**

- **オンボーディング（最初の一分）の判定は、一回目にしか下せない。**その一回を無駄にしない
- **段階2-b は、そのゲームで一度きりの機会である**

### 5. 「何を測るか」を、始める前に決めていない

〔Drachen ほか〕「設計と研究が最初に座って決めるほど良い」。
こちらは**触ってから測り方を考えている**（段階8 → 翻訳 → 測り方）。

**これは順番として逆だが、意図的に逆にしている。**
つまらなさは事前に予測できないので、生ログを先に取る。
**ただし「事前に決められるもの」まで後回しにしていないかは、毎回見ること。**
