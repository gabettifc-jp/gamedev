# 素材の一覧（写して、ゲーム側の `sozai.md` にする）

**何が要るかを、作る前に数える表。**

一本目（fishing-inc）には、この表が無かった。
**必要になった端からコードで描いたので、「全部で何枚要るか」を誰も数えたことがない。**
72匹の魚も、8つの釣り場も、途中で「まだ何枚残っているか」が言えなかった。

> **数えるのは、量を知るためだけではない。**
> 一覧が無いと、**探すことができない。**何が要るか分からないものは、
> 既製品を当たりようがない。だから全部自分で作ることになる。

---

## いつ書くか

**段階2-b（一回だけ作って触る）を抜けた直後。段階3の前。**

早く書く理由は二つ。

- **量が先に見えるほうが、諦める判断が早い。**「72匹」と先に書いてあれば、
  一匹目を描く前に「これは多い」と言える
- **段階3で仕様書を書くときに、この表が「画面に何が出るか」の裏取りになる**

**段階3のあとに回さない。**仕様書を書き終えてから数えると、
**すでに決めたものを数えるだけ**になって、減らす判断ができなくなる。

## 1. 絵

| # | 何 | どの画面 | コマ | 束 | 埋め方 | 名前 | いま |
|---|---|---|---|---|---|---|---|
| | | | | | | | |

**欄の意味。**

| 欄 | 何を書くか |
|---|---|
| **何** | 一つの単位。「主人公の待機」「魚（フナ）」「空」 |
| **どの画面** | 出る場所。二か所以上に出るなら全部書く（**片方だけ直す事故が防げる**） |
| **コマ** | 動きのコマ数。**動かないなら 1 と書く。**空欄にしない |
| **束** | **同じでなければならない相手。**同じ人物・同じ物なら同じ束の名前を書く |
| **埋め方** | 探す／生成／コードで描く／**要らない**（諦めたものも行として残す） |
| **名前** | 決めた名前。規則は下の3節 |
| **いま** | 未着手／**仮**／本番 |

### 「束」の欄がいちばん効く

> **2026-08-23、makeplay.ai に同じ題を作らせたら、
> 釣れた瞬間に左の老人が別人（中年の男）に置き換わった。**
> 待機・投げ・喜ぶの三枚を**別々に生成した**ため。
> 素材の検査は「枠に収まっているか」は見たが、**同じ人物かは見なかった。**

**束が同じ行は、一度に作る。**別々に作ると別物になる。
後から「同じにして」と言っても、**片方を作り直すしかない。**

## 2. 音

**キーはイベント名。ファイル名ではない。**

| # | イベント名 | 何のとき鳴るか | 役 | 音域 | 同時 | ファイル | いま |
|---|---|---|---|---|---|---|---|
| | | | | | | | |

| 欄 | 何を書くか |
|---|---|
| **イベント名** | コードが呼ぶ名前。`catch.perfect` のような形。**ファイルが差し替わっても変えない** |
| **役** | **ごほうび／仕掛け／予兆／地**の四つ。役が違う音を同じ束で作らない |
| **音域** | 高い／低い／持続。**役と音域の対応は、決めたら崩さない** |
| **同時** | 何回まで重なってよいか。**上限を書かないと、後半で潰れる** |

### なぜイベント名とファイルを分けるか

**コードが直接ファイル名を呼ぶと、差し替えのたびにコードを触ることになる。**
イベント名を挟むと、**表だけ書き換えれば音が変わる。**
一つのイベントに複数のファイルを割り当てて、鳴るたびに選ぶこともできる（連打が単調にならない）。

> **役と音域の対応は、先に決めて崩さない。**
> fishing-inc の決：「**報酬の音は高い音。低くて持続する音は予兆にだけ使う**」。
> **低い音が鳴ったら一つのことしか意味しない**、という状態を作るため。

---

## 3. 名前の規則

**先に決める。あとから直すと、全部の参照を追うことになる。**

```
<種類>-<対象>[-<状態>][-<番号>]

   raw-fish-funa.png        生成したまま。**まだ使わない**
   fish-funa.png            切って詰めたあと。**これを使う**
   fish-funa2.png           作り直した二枚目。**上書きしない**
```

- **生の素材と、加工後を、名前で分ける。**混ざると、どちらを使っているか分からなくなる
- **作り直しは番号で足す。上書きしない**（`builds/` の決まりと同じ思想）
- **参照元の作品名を入れない**（`CLAUDE.md` の禁止）

---

## 4. 仮の素材には、捨てる日を書く

`CLAUDE.md`「**仮のものには、捨てる日を書く**」が、そのまま当たる。

「いま」の欄が **仮** の行には、**必ず三つ**書く。

1. **使ってよい範囲**（どの画面まで仮で出してよいか）
2. **捨てる日**（どの時点で無条件に捨てるか）
3. **捨てたあと何をするか**

**「仮」とだけ書いた行は、永久に仮のまま生き残る。**

---

## 5. 数える

表が埋まったら、**合計を書く。**

```
絵     ◯行 ／ コマ合計 ◯ ／ 束 ◯個
       探す ◯ ／ 生成 ◯ ／ コードで描く ◯ ／ 要らない ◯
音     ◯イベント ／ ファイル ◯本
仮のまま ◯行（捨てる日が書いてある ◯行）
```

**この合計を見てから、段階3に入る。**多すぎると思ったら、**そこが減らす場所。**
