# 10 一回（プロトタイプ）

**このシートだけ、いちばん先に埋める。**（`flow.md` 段階2-b）

**目的は「面白いかどうかを、触って決められる状態にすること」。**
通しは作らない。経済も進行もメタも無し。**一回が繰り返されるだけのもの**を作る。

> **外の順番でいう prototype にあたる。**
> 「a prototype is where you find out if the core loop is fun at all；
> a vertical slice is where you show that fun at near-final quality」。
> **一本目（fishing-inc）は prototype を作らずに、いきなり縦切りを作った。**
> 投げる・叩く・売る・買う・転生が第一段に全部入っていた。

| 問い | 答え |
|---|---|
| **一回で、プレイヤーは何をするか**（動詞ひとつで） | |
| **一回は何秒か。**待ち・本体・返しに分けて | |
| **一回の中に、判断はあるか。**何と何のどちらを選ぶか。<br>**無いなら、それは作業である**（作業でよいなら、そう書く） | |
| **次に何をすべきかを、どれだけ前に、どんな形で伝えるか**（秒とミリ秒で） | |
| **成功したとき、何が返るか。**音・画面。**どこに出るか**（操作した対象そのものか、画面の隅か） | |
| **失敗したとき、何が返るか。**成功と何が違うか | |
| **返しが何も出ない入力が在るか。**外し方を一つずつ数える | |
| **許容の幅は何段階で、どれだけか**（ミリ秒・画素・回数） | |
| **もう一回やりたくなる理由は、一回の中に在るか、外に在るか。**<br>外（金・進行・収集）に在るなら、**この段では確かめられない** | |
| **何回繰り返したら飽きるか。**触って数える | |

## 埋め方

- **ジャンルシートの相場のうち、分野1〜4だけを見る**（入力と判定／返し／見せ方と予告／構造）。
  **5〜7（進行と難度・遊んだ人の文句・実装の落とし穴）は、この段では見ない**
- 数値は数値で書く。「速い」ではなく「450ミリ秒」

## この段を抜ける条件

**「もう一回やりたい」になること。**設計者が触って判定する。

- **ならなければ、段階3へ進まない。**一回を直すか、核から作り直す
- **通しの問いを埋めて誤魔化さない。**58問埋めても、一回が面白くなければ意味がない

> **一回が面白いかどうかは、一回でしか分からない。**
> fishing-inc で「リズムゲーム自体はかなり癖になる」と分かったのは、
> **触ったからで、78問埋めたからではない。**
