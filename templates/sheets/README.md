# templates/sheets/

**空欄のあるシート。**項目を並べるだけでは守れなかったので、埋める形にした。

## 使い方（二段）

**シートは二つの束に分かれる。一回を触れるようにする束と、通しを作る束。**

### 一段目 ── 一回（`flow.md` 段階2-b）

1. `00-kihon.md` を写して埋める
2. **`10-prototype.md` だけを埋める**（10問）
3. **一回だけを実装して、触る**
4. **「もう一回やりたい」になるまで、ここを回る。ならなければ二段目へ進まない**

### 二段目 ── 通し（`flow.md` 段階3）

5. 00 の答えで配られたシートを、順に埋める
   （**ジャンルシートは、固有の問いだけを写して埋める。**相場は写さない。下の「ジャンルシートの写し方」）
6. **すべてのシートに空欄が無くなったら、埋め終わり**
   （**印が付いた欄は、埋まったものとして数える。**下の「欄の三つの状態」）

> **なぜ二段にするか。**
> 一本目（fishing-inc）は一段で回した。全部埋めてから作ったので、
> **触れるようになったのが最後**になり、そこから**決を五件ひっくり返した**
> （キーサウンド／カウントインの音／窓の外の向き／長音の頭／開く型の値段）。
> **決は「触る前に決めたこと」だった。**
>
> 問いの数でいうと、通しの束は58問。**一回の手触りには効かない。**
> **効く35問（01・06・08）より先に、58問を埋めていた。**

手で書いてもよいし、道具を使ってもよい。

## シートは足場であって、正本ではない（決）

**埋め終わったら、そこから仕様書を書く。以後、シートは触らない。**

| | 役目 |
|---|---|
| **シート** | **渡す前に、抜けを潰すための足場。**一度きり使って、そのまま置く |
| **仕様書** | **正本。**ここから先は、こちらだけを直す |

**シートが古くなるのは正しい。**直さない。

> **なぜこうするか。**実際にそうなっていた。
> fishing-inc のシートは第一段のまま止まり、**仕様書は第30版まで進んだ。**
> 遡って根拠を付けたら、**12件が古くなっていて、誰も気づいていなかった**
> （一回の秒数・通しの時間・パークの数・魚の種類数・押した瞬間の返し・長音の離し・
> 距離の上限・縮む輪…）。
>
> **二つを両方直し続けるのは、二重管理である。**
> 足場と決めれば、古くなっても壊れない。
> **古いシートを読んだ人が仕様書と食い違うのを防ぐため、シートの先頭に
> 「これは足場。正本は仕様書」と書いておく。**

> **だから、シートと仕様書の版が合っているかは検査しない。**
> `src` の版マーカーは仕様書と照らすが、**シートは照らさない。**
> 合わないのが正常だからである。

## 答えは Claude が先に埋める。設計者は触ってから否定する

**空欄を設計者に渡さない。**設計者に答えられる問いは、実際には少ない。
結局 Claude に聞きながら埋めることになるので、**先に Claude が埋めて渡す。**

| | やること |
|---|---|
| **Claude** | **全部の欄を先に埋める。**一つずつ**根拠**を付ける |
| **設計者** | **触ってから「これは違う」と言う。**埋めるのを手伝わない |

**設計者が先に答えるのは、Claude には出せないものだけ。**
何を作りたいか、面白さの核の一文、面白いと思う仮説（`flow.md` 段階1・2）。

## 根拠の欄

**答えを書いたら、必ず根拠を書く。**根拠は `CLAUDE.md` の判断の四分類で示す。

| 印 | 意味 | 書き方 |
|---|---|---|
| **1** | **調べれば決まる** | `1〔相場：見た目 4.5:1〕` のように**出どころを添える** |
| **2** | **上位の決定から導ける** | `2〔3章の一拍0.25秒から〕` のように**どこから導いたかを書く** |
| **3** | **触らないと分からない** | 触る前は `3〔未〕`、触った後は `3〔実測：◯◯と出た〕` |
| **4** | **根拠がない。置いただけ** | **`4〔置いただけ〕`。これを隠さない** |

> **4を隠さないことが、この欄の本体である。**
> 2026-08-21、旋律の作り方を**根拠なしで作って、根拠があるように出した。**
> 「34本を全部ちがう旋律にする」という指標も、**こちらが勝手に置いたもの**だった。
> **二本作って二本とも捨てられた。**
> 最初に `4〔置いただけ〕` と書いてあれば、一本目で止まった。

> **根拠が空の答えは、答えではない。**
> 埋まったかどうかを数えるときは、**答えと根拠の両方が在る欄だけを数える。**

## 欄の三つの状態

**配られるのはシート単位なので、そのゲームには要らない問いも混ざる。**
配りかたを問い単位に細かくするのではなく、**配ってから間引く。**
問いが落ちるのは見えないが、空欄は見えるからである。

| 欄の状態 | 意味 |
|---|---|
| 空 | **まだ見ていない** |
| 〔このゲームには要らない〕 | **見て、このゲームには要らないと決めた** |
| 答えが書いてある | 埋めた |

- **印を付けるのは、相談して決めたときだけ。**一人で決めない
- **なぜ要らないかを、印の後ろに一行書く。**
  例：`〔このゲームには要らない〕終わりが無いため`
- **印は消さずに残す。**後で要ると分かったら、答えに書き換える

> **印は「要らない」であって「分からない」ではない。**
> 見て決めたときだけ付ける。迷っているあいだは空のままにする。

> **`genre/` の〔相場が取れなかった〕とは別の印。**
> あちらは**調べる側**の話で「調べたが相場が無かった」。
> こちらは**作る側**の話で「このゲームには要らない」。混ぜない。

## 道具（`tools/sheets.html`）

開き方は二つある。

### 1. ファイルに保存する（おすすめ）

```
node tools/serve.mjs ../fishing-inc/sheets
```

置き場を指定して立ち上げ、出てきた `http://127.0.0.1:5173/` を開く。
**書き込んだ内容が、その場所の `00-kihon.md` 〜 `09-loop-chart.md` にそのまま保存される。**

- 置き場が無ければ作る。空なら空のシートから始まる
- 書き込むたびに保存する（0.4秒ほどまとめてから）。左下に「保存した」と出る
- 開き直すと、置き場のファイルから読み直す
- 港を変えるには `--port=5199`
- `127.0.0.1` にだけ開く。指定した置き場の外は読み書きしない

### 2. ダブルクリックで開く

`tools/sheets.html` をそのまま開く。**サーバは要らない**が、
**ファイルには保存されない**（ブラウザのなかに残るだけ）。
書き出しボタンで markdown を出し、自分で貼り付けて保存する。

- 10枚を表で出し、**空欄に直接書き込める**。空欄は薄い黄色で、埋めると消える
- 左の一覧に**埋まり具合**（「3／10」）が出る
- `00` を埋めると、**配布の規則どおりに一覧が絞られる**。
  配られないシートは暗くなるが、押せば見られる
- **書き出す**を押すと、この `templates/sheets/` と同じ形の markdown が出る。
  10枚まとめてと、1枚ずつの両方
- 書いた markdown を貼れば**読み込める**。途中から続けられる
- 書いた内容は**ブラウザに残る**。閉じて開き直しても消えない
- `02` の層、`03` の時間の区切りと種類、`07` のつまみ、`09` の周と決めることは、**行を足せる**。
  行を足せる表は、あらかじめ文字が入っている欄も書き換えられる（既定値のつもり）

### 図（表に入れると、その場で変わる）

| シート | 図 | 何が見えるか |
|---|---|---|
| `02` | **層の帯** | 層ごとに、通しのどこまで届くか。**白い部分がそのまま穴** |
| `03` | **強度のグラフ** | 時点ごとの強度を棒で。単調・空白・終盤が最大、を自動で言う |
| `07` | **曲線** | 指数で伸びるものを対数目盛りで重ねる。交差する点と跳ねる点が見える |

**図は表の写し。**図の側では編集しない。

### つじつま（左の一覧の下）

シートをまたいで計算し、合わなければ赤くする。

- 通しの時間 … 02の（一巡の長さ×回数）の合計 ≒ 00の「通しで何時間」
- 一巡の中身 … 02のメタ1の一巡 ÷ 01の「一回は何秒か」＝ 一巡あたりの回数
- ビートチャートの全長 … 03の最後の時点 ≒ 00の「通しで何時間」

計算に要る欄が空なら「計算できない（◯◯が空）」と出る。黙って何も出さないことはしない。

> 道具のなかにシートの中身が写してある（`file://` では読み込みができないため）。
> **シートを直したら、道具のなかの写しも直すこと。**
> **`node tools/check-sheets.mjs` が、写しとシートを照合する。**
> あわせて、ジャンルシートの相場表が参照している問いが実在するかも見る。

## ジャンルシートの写し方

**相場は写さない。ゲーム側に写すのは「固有の問い」の表だけ。**

- **相場**は、00〜09 の問いに対する答えの目安。**答えは 00〜09 のシートに書く。**
  ジャンルシートを丸ごと写すと、相場がゲームの数だけ増えて、直す場所が散る
- **固有の問い**は、汎用シートに行き先が無いもの。**これはゲームが答えるので、ゲーム側に要る**
- ゲーム側のファイルは、相場の在り処（`gamedev/templates/sheets/genre/*.md`）を一行で指す

> **ジャンルシート（`genre/`）は、まだ道具に載っていない。**
> 枚数が可変で、保存先の名前が `00`〜`09` の固定の並びから外れるため。
> **いまは手で書く。**

| シート | いつ配られるか |

| `00-kihon.md` | 最初に必ず |

| `08-input.md` | 常に |
| `02-meta-loop.md` | 通しが1時間を超える |
| `03-beat-chart.md` | 新しいものが順に出る |
| `04-arc.md` | 尽きるものがある |
| `05-endgame.md` | 終わりがある |

| `07-tunables.md` | 数値で調整するものがある |

`spec.md` / `checklist.md` / `prompt.md` / `check.md` は、これまでどおり使う。
シートは仕様書を書く前の工程で、`spec.md` はその結果を書き留めるところ。
