# templates/sheets/genre/

**ジャンルシートの書き方と入れる基準は、ここが正本。**
flow.md 段階0-b と、各ジャンルシートの冒頭は、ここを指している。

## ジャンルシートとは何か

**そのジャンルで既に解かれている問題の、答えの相場を持つもの。**

**問いは持たない。**問いは 00〜09 のシートに在る。
ジャンルシートが持つのは、**その問いに対する、そのジャンルでの答えの相場**だけ。

読み物ではない。`references/` は読んで終わる。

## 調べる分野（この七つを、必ず上から当たる）

**一つの分野につき、最低一つの出どころを取る。ゼロ本の分野は、ゼロ本だと書く。**

| 分野 | 何を聞くか |
|---|---|
| 1. 入力と判定 | 幅・段・窓。何をどれだけ許すか |
| 2. 返し | 成功／失敗のとき、音と画面で何が返るか |
| **3. 見せ方と予告** | **次に何をするかを、いつ・どんな形で伝えるか** |
| 4. 構造 | **そのジャンルの気持ちよさの本体はどこか。**表面の作りではないほう |
| 5. 進行と難度 | 何で難しくするか。何を伸ばすか |
| 6. 遊んだ人の文句 | 講評・掲示板。**作り手の資料には出てこない層** |
| 7. 実装の落とし穴 | 遅れ・較正・端末差 |

> **この一覧は、穴が開いてから作った。**
> 音ゲーのシートは第2版まで、出どころ七つが**判定・返し・音の資料ばかり**で、
> **3（見せ方と予告）を扱う資料を一本も読んでいなかった。**
> そのため「押すタイミングをどう伝えるか」が、設計者に言われるまで出てこなかった。
> **問いの形が悪かったのではなく、答えが在る場所を見ていなかった。**

## 書式（三つの部）

### 1. 相場（本体）

| どのシートの、どの問いか | ○○での相場 | 出どころ | 外すと何が起きるか |

**一行めは、参照する問いを逐語で持つ。**`08「…」` の形。
シートの問いを直したら、`node tools/check-sheets.mjs` が突き合わせて、直す行を見つける。

- **「答え」の欄は置かない。**答えはシートの側に書く。二か所あると必ず食い違う
- **「外すと何が起きるか」は、ここに残す。**要否の判断材料なので
- **調べていない問いには行を作らない。**
  〔相場が取れなかった〕は「調べたが無かった」の印で、行が無いのとは別のこと

### 2. そのジャンル固有の問い

**汎用シートに行き先が無いものだけ。ここだけ問いの形で持つ。**

### 3. 出どころの記号

そのシートで使った記号の対応表。**〔実測〕を含める。**

## 〔実測〕── 触って出した相場

**調べても出なかった相場が、触ると出ることがある。**
そのときは出どころを **〔実測〕** にする。どのゲームのどの版で触ったかを添える。

**外から採った相場と、触って出した相場を、後から区別できるようにするため。**
外の相場は他のゲームでも使えるが、触って出した相場は自分の盤面に紐付いている。

## 入れる基準

**「外すと、遊んだ人が概念ではなく作りに文句を言う」ものだけ。**

概念の判定（面白いかどうか）を邪魔しないものは入れない。
スコアの式、ランクの表示、難易度の数値化などがこれにあたる。

## 各項目に「外すと何が起きるか」を必ず付ける

要否はこれを見て判断する。付いていない項目は、要るかどうかが判断できない。

## 値は幅で書く

**出どころが割れたら、割れたまま残す。一本に決めない。**

取れなかったものは **〔相場が取れなかった〕** と印を付けて残す。
空欄と「調べたが無かった」は別のことなので、区別が消えないようにする。

## いま在るもの

**この置き場を見る。**一覧は作らない（増やすたびに二か所を直すことになる）。
