# ジャンルシート：音ゲー

第1版／2026-08-19／置き場の案：`gamedev/templates/sheets/genre/rhythm.md`

**これは調査の成果物であり、そのまま埋める欄でもある。**
読み物としての調査（`references/`）とは別。あちらは読んで終わるが、こちらは空欄が残る。

## 入れる基準

**「外すと、遊んだ人が概念ではなく作りに文句を言う」ものだけ。**
スコアの式、ランク表示、難易度の数値化などは、無くても概念の判定を邪魔しないので入れていない。

各項目に**「外すと何が起きるか」**を付けてある。要否はこれを見て判断する。

## 出どころ

| 記号 | 出どころ |
|---|---|
| 〔比較表〕 | コミュニティが作った、数十本の音ゲーの判定窓の比較表（ZIv フォーラム） |
| 〔RH〕 | Rhythm Horizon の公開仕様 |
| 〔講評〕 | itch.io のジャム作品に付いた遊んだ人の講評（複数件） |
| 〔開発者〕 | Rhythm Quest 開発日誌、Native Audio の音ゲー講座 |
| 〔ETC〕 | カーネギーメロン ETC「音ゲーの音の設計」 |
| 〔解説〕 | 譜面制作の解説サイト・用語集 |

> **値は幅で書いてある。**同じ検索で最高判定が ±15ms と ±67ms の両方出た。
> 出どころが割れたものは、割れたまま幅で残す。**一本に決めない。**

## 1. 判定

| 問い | 答え | 相場 | 外すと何が起きるか |
|---|---|---|---|
| 判定は何段階か。各段の窓は何ミリ秒か | | 最高判定 ±15〜30ms（競技系）／±40〜67ms（緩め）。コンボが切れない下限は ±100ms前後〔比較表〕〔RH〕 | 完璧が出せる気がしない |
| **早いか遅いかを表示するか** | | 最高判定とMISS以外の全判定で EARLY／LATE を出す〔RH〕 | **直しようがない。「正しいタイミングが分かりにくすぎる」** |
| 判定の目印は画面のどこにあるか | | 符号が来る線を固定で置く | いつ押すか分からない |
| 判定の結果は何段階の言葉で出すか | | 完璧／良／可／失敗 の3〜5段が普通 | 上達した実感が出ない |

---

## 2. 外れた入力の扱い

**ここが一番落ちる。**「正しく押したとき」だけ書いて渡すと、全部ここが穴になる。

| 問い | 答え | 相場 | 外すと何が起きるか |
|---|---|---|---|
| **判定窓の外で押したらどうなるか** | | **窓の外の入力は符号を消さない。**連打で先の符号が消える作りは **mashing** と呼ばれ、そう判断した判定を無視する仕組みを入れる〔RH〕。ジャム作品の講評でも「完全な見逃しか、早い／遅いの窓内で押したときだけ消せ」と処方されている〔講評〕 | **「どんなに離れてても押せば次の符号が反応する」** |
| 何も押さずに通り過ぎたらどうなるか | | 見逃しとして失敗扱い | 押さないほうが得になりうる |
| **符号どうしの最小間隔はいくつか** | | 〔相場が取れなかった〕定量の値は出てこない。定性としては「符号どうしが読めなくなる詰め方をしない」〔解説〕 | **「長音のすぐ後に符号があるとどちらか押せない」** |
| 同時に複数の符号を受けるか | | | 入力が競合して片方が死ぬ |

## 3. 長押し

| 問い | 答え | 相場 | 外すと何が起きるか |
|---|---|---|---|
| 長押しは何で判定するか | | **押し始めの正確さと、最後まで保持できたかの両方。**途中で離すのは **dropping a hold** と呼ばれ、脱落として扱う〔解説〕 | 長押しが単押しと同じになる |
| 離す許容は何ミリ秒か | | 200ms 以上離すと脱落〔RH〕 | 一瞬の指の浮きで落ちる |
| **離しのタイミングを判定するなら、それをどう伝えるか** | | | **「離しを合わせるとは思わなかった。押しっぱなしにするのが本能だった」〔講評〕** |
| 長押しの直後に符号を置くか | | 置くなら、離しと次の押しが両立する間隔を空ける | 上の2と同じ穴 |

## 4. 返し（押した瞬間に何が返るか）

**講評でいちばん多く出る指摘がここ。**

| 問い | 答え | 相場 | 外すと何が起きるか |
|---|---|---|---|
| **押した瞬間に音を返すか** | | 打鍵音は必須に近い。無いと**「耳が聞こえないまま音ゲーをしているようだ」**という講評が付く。合っていても間違えた気がする〔講評〕 | **合っていることが分からない** |
| 押した瞬間に画面が返すか | | **符号そのものが反応する必要がある。**符号が消えるだけ、画面の隅に文字が出るだけ、では足りないという講評が繰り返し出る〔講評〕 | 押したか分からず、画面の隅を見続けることになる |
| 打鍵音は曲と混ざらないか | | 合図の音が曲の音に近すぎると、いつ押すか分からなくなる〔ETC〕。合図の音は全編で同一に保つ | 曲が合図を食う |
| 失敗したときも返すか | | | 間違いに気づかない |

## 5. ずれ（較正）

| 問い | 答え | 相場 | 外すと何が起きるか |
|---|---|---|---|
| ずれを合わせる手段があるか | | **ずれは三種類（音の出／画面の描画／入力）。**装置ごとに違うので自動では決まらず、ほとんどの音ゲーが起動時に較正を置く〔開発者〕 | 上手い人ほど「判定がおかしい」と言う |
| 較正した値は毎回同じに戻るか | | 起動のたびにずれる作りは**開発側の誤り**とされている〔開発者〕 | 較正画面に何度も戻される |
| ブラウザで動かすなら、そのぶんのずれを見込むか | | ブラウザの音は特に遅い | 全体が遅れて、全員が早く押す癖になる |

## 6. 譜面と曲

| 問い | 答え | 相場 | 外すと何が起きるか |
|---|---|---|---|
| 譜面は曲のどこに合うか（BPMと開始のずれ） | | **BPMが0.01ずれるだけで、曲の後半で目に見えてずれる**〔解説〕 | 後半だけ合わなくなる |
| 始まりに準備の拍を置くか | | | 一つ目の符号を必ず落とす |
| 難しさは何で上げるか | | 速さで上げると、覚えたことの意味が消える | 理不尽になる／格の差が伝わらない |

## fishing-inc に当てたらどうなったか（検証）

がべが実際に遊んで出した音ゲーの不満は三つ。**三つとも、このシートの太字の欄に対応する。**

| 出た不満 | 対応する欄 |
|---|---|
| どのタイミングで押せば完璧か分からない／正しいタイミングが分かりにくすぎる | 1「早いか遅いかを表示するか」 |
| どんなに離れてても押せば次の符号が反応する | 2「判定窓の外で押したらどうなるか」 |
| 長音のすぐ後に符号があるとどちらか押せない | 2「符号どうしの最小間隔」／3「長押しの直後に符号を置くか」 |

**このシートが先にあれば、三つとも設計の時点で欄として見えていた。**
